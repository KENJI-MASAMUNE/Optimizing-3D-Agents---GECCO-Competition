# Implementation audit — October 2026

Everything below was checked against the **real Framsticks 5.5 simulator** (the Linux
`frams-objects.so` from the project's `Framsticks55` folder, run on Linux), not only the
unit-test double. Test suite: 52 tests pass (`pytest tests -q`), including 16 new regression
tests in `tests/test_audit_fixes.py`.

## 1. The determinism fix (FramsticksLib.getRandomGenotype)

**Verdict: the change is valid, and it was necessary — but it was not sufficient.**

| Check (fresh processes, same seed) | Result |
|---|---|
| Upstream line `np.random.default_rng().integers(...)` | different initial population every process (bug confirmed) |
| Patched line `np.random.randint(...)` | byte-identical populations |
| Upstream framspy today (svn) | still has the `default_rng()` bug |

Why the patch is valid: `default_rng().integers(a, b+1)` and `randint(a, b+1)` both draw
uniformly from `[a, b]`, so the distribution of random genotypes is unchanged; only the
source of randomness changes from OS entropy to the seeded global NumPy RNG.

We no longer depend on the patch: `ProjectFramsticksLibCompetition.getRandomGenotype()`
(src/framsticks_interface/competition_lib.py) overrides it with a per-run seeded
`np.random.Generator`. An unpatched framspy (e.g. a fresh copy on the CHPC) now behaves
identically. Keeping the patched file on your laptop does no harm.

Two further findings about the native RNG:

* `frams.Math.seed` is 0 right after `frams.init()` and the native RNG is already
  deterministic as long as `Math.randomize()` is not called (which `DETERMINISTIC=True`
  prevents). The earlier "native RNG is non-deterministic" observation was really the
  NumPy bug above. Assigning `frams.Math.seed = s` is still correct and useful: it re-seeds
  and can be re-assigned mid-process.
* **New bug found and fixed:** Framsticks' Gaussian generator (Marsaglia polar method)
  caches the second value of each pair, and `Math.seed = s` does **not** clear that cache:
  `seed 42 → rndGaussStd` repeated gives `-0.517, 1.222, -0.517, 1.222, …`. Mutation uses
  Gaussian draws, so a run's result depended on what ran before it in the same process
  (measured: one run scored 0.148 when executed first and 0.219 when executed after
  another run). The old two-process check could not see this because each check ran in a
  fresh process. `reset_native_rng()` in interface.py now empties the cache on every
  reseed and verifies the post-condition.

`RealFramsticksInterface.reseed(seed)` now resets Python `random`, NumPy, the
getRandomGenotype generator and the native RNG (including the Gaussian cache), and
`run_single`/`run_spec` call it at the start of every run. Verified with
`scripts/verify_reproducibility.py`: sequential vs process pool vs isolated runs in reverse
order with a different `PYTHONHASHSEED` → identical best fitness, best genotype and
per-generation history for every run.

## 3. Performance improvements (no change to results)

* `framsticks_sim/recording-cog-only.sim` (`STORE_ALL_PART_COORDS = 0`): identical COG path,
  **~9× faster** evaluation (0.20 s → 0.02 s per evaluation at Energy0 2500).
* Dissimilarity matrix computed once per selection step and reused for all fronts; graph
  distances cached per genotype pair within a run (the proposal's "memorised cache").
* Per-run fitness cache: genotypes already simulated in this run are not re-simulated
  (deterministic evaluation) — ~30% of evaluations saved in full-size runs.

Measured full-size runs (pop 100 × 60 generations, straight_line_cog): 3–8 CPU-minutes each
(graph variant on f1 is the slowest), best fitness rising from 0.147 to 0.39–0.45.

## 4. Things that are a research decision (flagged, not changed)

* **Energy0 = 2500** is fixed in `configs/*.yaml → framsticks.base_world` to match the
  `eval-allcriteria.sim` in your local Framsticks55/data (stock file: 10000). Your earlier
  sweep found 5000 gave higher fitness (longer trajectories). Changing it changes every
  task's difficulty and doubles run time; decide before launching Phase 1.
* **`straight_line_cog` target distance = 10 units** over the lifespan. Random creatures
  barely move (fitness ≈ 0.147 for almost everyone at generation 0), so early selection is
  driven mostly by the diversity objective. Evolution does make progress (0.40–0.45 after
  60 generations), so it works, but it is worth a sentence in the report.
* ~~**`sinusoidal_bounce` targets absolute height**~~ (fixed after Phase 1 -- see #9) (0.5 + 0.1 sin(t/100)). In worlds where
  the ground is raised (blocks, hills) or the creature floats (water), the score partly
  reflects terrain height rather than bouncing, which matters when interpreting Phase 3
  generalisation for S02/S05. A relative-height variant would be a one-line change if you
  prefer it.
